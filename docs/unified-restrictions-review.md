# Общая система ограничений и скорость каталога

Владелец попросил включить ранее скрытые марки в существующий анализ АвтоВАЗа
при загрузке Excel и убрать задержки списка, пагинации и возврата из карточки.

## Результат

- Раздел переименован в «Ограниченные товары»; сохранён существующий компактный
  интерфейс и привычный процесс загрузки/публикации прайса.
- АвтоВАЗ/LADA, ГАЗ/НАЗ, КАМАЗ, Hyundai, Kia, WABCO, BMW, Mitsubishi и Лукойл
  оцениваются общей системой. Новые марки не добавлялись.
- Владелец может подтвердить разрешение; сотрудник не может менять решения.
  Неизменённые решения сохраняются при повторном импорте. Устаревшие решения
  не разрешают изменившиеся товары автоматически.
- Публичные запросы используют свежие сохранённые оценки вместо большого
  регулярного выражения для каждого товара. Старый формат поддерживается
  на время управляемого обновления; защита не отключается.
- Данные карточки для метаданных и страницы читаются один раз на запрос,
  без постоянного кэша разрешений между посетителями.

## Проверка

`pnpm typecheck`, `pnpm test`, `pnpm build` прошли на отдельной Linux-сборке.
Добавлены 22 проверки общей классификации. Пройден существующий набор из 31
изолированной проверки PostgreSQL/Meilisearch и новый сценарий выбранных марок,
21 адреса, прав владельца/сотрудника, перехода со старого формата, настоящего
Excel и публикации обычным worker. Проверены подтверждение/отмена владельцем,
права сотрудника и отсутствие горизонтального переполнения на мобильном экране.

На 25 000 одинаковых искусственных товаров медиана открытия списка составила
1091 мс до подготовки и 106 мс после; количество осталось 20 066 в обоих случаях.
Это сравнение тестовой базы, а не обещание такой же задержки на любом соединении.

## Почему в PR patch

GitHub main не содержит уже работающую систему АвтоВАЗа и часть других ранее
установленных изменений. Поэтому этот draft содержит проверяемый application
patch к действующей версии, а не заменяет сайт устаревшим main и не публикует
посторонние незакоммиченные изменения владельца.

Изменения приложения и тестов находятся в
`patches/unified-restrictions-2026-11-13.patch`. Правила применения и изменения
описаны внутри patch в `docs/unified-restrictions.md`.

Пакет не выполняет миграцию, публикацию или активацию при слиянии PR. Установка
требует отдельного разрешения: обновление приложения и worker, подготовка оценок
действующего каталога и поискового индекса, проверка и управляемая активация.
Схема БД, исходные товарные записи и инфраструктура этим patch не меняются.
